# Deployment handoff — wait for explicit authorization

The user requires local review before any deployment. Nothing in this checklist authorizes deployment.

## Completion certificate and cryptographic seal

The completion certificate is generated by the application. It includes captured signature images, signing events, consent, request IPs and document hashes. It does not require buying a certificate. Location must not be fabricated from the sample screenshot or an unverified request header.

Before production, configure and test the separate cryptographic PDF seal:

- Obtain the operator's authorized signing certificate and private key. Determine whether the intended PDF readers trust its issuing chain; a self-signed test certificate is not publicly trusted.
- Install the optional `sealing` dependencies in the Frappe Cloud build.
- Provision the PKCS#12 file securely outside the public repo and web-accessible files. Set `esign_pkcs12_path` and `esign_pkcs12_password` privately on the target site.
- Configure `esign_timestamp_url` for the chosen trusted timestamp service, including its access requirements. The current client uses the supplied URL; providers requiring additional authentication may require adapter work.
- Set `esign_require_seal` only once seal generation and failure/retry behavior have been tested successfully in staging.
- Validate both the completed document and completion certificate in an independent PDF validator, including trust chain, timestamp and certificate expiry. Plan certificate renewal and restricted key access.
- Confirm backups, finalization workers, email delivery, ERP record permissions and the hosting plan's requirements before production use.

No signing key, certificate purchase, timestamp service or production configuration has been created by this change. Revisit this checklist when the user explicitly requests deployment.
